REST API

📐

Основные принципы REST

01

Клиент-Сервер

Разделение интерфейса и хранения данных для независимой эволюции

02

Отсутствие состояния

Каждый запрос содержит всю необходимую информацию для обработки

03

Кэширование

Ответы должны быть помечены как кэшируемые для повышения производительности

04

Единообразие интерфейса

Стандартизация методов, форматов и идентификаторов ресурсов

05

Слои

Промежуточные серверы для балансировки нагрузки и безопасности

06

Код по требованию

Расширение функционала через загрузку исполняемого кода (опционально)

⚡

HTTP Методы REST API

GET read
Получение данных. Безопасный и идемпотентный метод
GET /api/users/123 GET /api/products?page=1
200 OK 404 Not Found
POST create
Создание нового ресурса. Не идемпотентный метод
POST /api/users { "name": "John", "email": "john@ex.com" }
201 Created 400 Bad Request
PUT update
Полное обновление ресурса. Идемпотентный метод
PUT /api/users/123 { "name": "John", "email": "new@ex.com" }
200 OK 204 No Content
PATCH partial update
Частичное обновление ресурса. Не идемпотентный
PATCH /api/users/123 { "email": "new@ex.com" }
200 OK 204 No Content
DELETE delete
Удаление ресурса. Идемпотентный метод
DELETE /api/users/123
200 OK 204 No Content 404 Not Found
